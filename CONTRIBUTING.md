# Contributing

## Documentation contribution rules

1. Keep public concepts simple.
2. Add examples for every new concept.
3. Update ADRs for architectural decisions.
4. Update MVP scope if a change affects implementation priority.
5. Update security docs if a change affects tools, memory, hooks, skills, or extensions.
6. Update eval docs if a change affects release gates.

## Review checklist

- [ ] Does this preserve tools-first UX?
- [ ] Does this preserve lightweight skills?
- [ ] Does this keep policy-before-tool-call?
- [ ] Does this preserve evidence-backed claims?
- [ ] Does this preserve immutable run snapshots?
- [ ] Does this keep MVP thin and executable?
